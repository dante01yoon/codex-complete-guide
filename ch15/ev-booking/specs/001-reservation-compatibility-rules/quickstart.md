# Quickstart Validation: 순수 예약 규칙

US1 테스트·구현과 실행 기반을 준비했다. 아래 절차 중 US1은 validation.md의 실제 기록을 따르며, US2·US3은 미착수다.
패키지·테스트·구현 파일이 준비되기 전 명령이 실행 가능하다고 보고하지 않는다.
전체 모바일 앱의 검증이 아니라 입력 → 규칙 판정 결과의 모듈 검증이다.

## Prerequisites

- Node.js 24. 이번 계획에서 `node --version` 결과는 `v24.14.1`이다.
- [contracts/rules.md](contracts/rules.md)의 공개 진입점과 정상 입력 전제.
- [data-model.md](data-model.md)의 시간·커넥터 모델.
- 후속 테스트 준비 작업에서 package.json·잠금 파일·TypeScript·Vitest 설정을 만든다.
  ESM·Node 환경, strict 타입 검사, `test:rules`와 `typecheck` 스크립트를 사용한다.
- 화면·저장소·테스트 계정·토스 키·서버·원본 파일은 이 검증에 필요하지 않다.

## 1. 테스트 실행 기반 준비 (후속 단계)

예정된 최초 개발 도구 설치 명령:

```sh
npm install --save-dev typescript vitest @types/node
```

Node 24 호환 버전을 확인하고 설치된 버전을 잠금 파일에 고정한다.
잠금 파일이 있는 후속 재현 환경에서는 `npm ci`를 사용한다.
예정 스크립트는 `test:rules` = `vitest run tests/rules`,
`typecheck` = `tsc --noEmit`이다. US1 실행 기반은 설치·스크립트 작성을 완료했으며 실제 버전은 validation.md에 기록했다.

실행 가능한 함수 선언·미구현 진입점을 테스트 준비에서 마련하되 제품 로직은 작성하지 않는다.
의존성 누락·import 실패·설정 오류를 기능 실패로 간주하지 않는다.

## 2. AC별 테스트 작성과 사용자 확인

계약의 Test traceability 표에 따라 테스트를 먼저 작성한다.
테스트 이름에 원문 AC와 S 번호를 넣고, 커넥터 66조합 기대값은 PRD에서 독립 작성한다.
다음은 확인 대상이며 완성 테스트 코드는 이 문서에 포함하지 않는다.

| 테스트 그룹 | 시나리오 | 필수 결과 |
|---|---|---|
| 겹침·식별 | S-01~S-07 | 부분·동일·포함 거절, 양방향 연속 허용, 다른 충전기 제외 |
| 커넥터 | S-08~S-12 | 알려진 66조합과 표 일치, 복합 타입 판정 |
| 결합·기존 제한 | S-13~S-16 | 하나라도 실패하면 rulesPassed=false, 기존 자격 false 유지 |
| 순수성 | 위 입력 반복·동결 | 동일 결과, 중첩 입력 불변, 외부 상태와 I/O 없음 |

테스트 파일·입력·기대 결과·AC 대응을 사용자에게 제시한다.
사용자가 그 테스트를 확인한 뒤 파일 목록과 SHA-256을 기록한다.
계획이나 명세 승인을 이 단계의 사용자 확인으로 대신하지 않는다.

## 3. 실제 실패 확인 (Red)

사용자 테스트 확인을 받은 후 아래 명령을 실행한다.

```sh
npm run test:rules
```

함수는 호출되지만 아직 미구현이므로 각 구현 대상 AC의 실패가 확인되어야 한다.
명령·실패 AC·S·기대와 실제 결과·실패 원인을 기록한다.
도구 실행이 막히면 BLOCKED, 실행하지 않으면 NOT_RUN이며 구현으로 넘어가지 않는다.
예상 실패는 FAIL로 기록하되 헌법의 실패 관문 증거로 구분한다.

## 4. 구현과 통과 확인 (Green)

사용자 확인과 Red 증거를 모두 갖춘 뒤 src/rules의 구현만 진행한다.
테스트 파일·기대값·스킵 상태·실행 제외 설정을 바꾸어 통과시키지 않는다.

```sh
npm run test:rules
npm run typecheck
```

계약·시나리오 기대값과 일치해야 하고 타입 검사도 오류가 없어야 한다.
승인한 테스트의 SHA-256이 구현 전후 같은지 확인한다.
테스트 오류가 발견되면 구현을 중단하고 별도 테스트 단계에서 재확인·실패 확인 후 재개한다.

## 5. 결과 보고

AC별 실제 실행 결과를 PASS / FAIL / BLOCKED / NOT_RUN으로 기록한다.
AC-01-1은 식별 비교, AC-02-6은 결과 사유, AC-02-8은 기존 제한 전달 부분만 검증한다.
화면 안내, 전체 예약 확정, 원자적 점유 생성 또는 전체 AC가 통과했다고 확대하지 않는다.

| 항목 | 현재 상태 |
|---|---|
| Node.js 24 버전 확인 | PASS: v24.14.1 |
| 계획·모델·계약 문서 정적 검토 | PASS |
| 도구 설치·테스트 기반 생성 | PASS (US1 실행 기반) |
| US1 테스트 작성·사용자 확인·Red·Green | 완료: Red 31건 FAIL → Green 31건 PASS |
| US2·US3 테스트·구현 | NOT_RUN |
| 타입 검사 | PASS: npm run typecheck, exit 0 |
| 화면·저장소·브라우저·토스 실연결 | NOT_RUN (이번 범위 제외) |

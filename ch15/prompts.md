# 15장 요청 프롬프트

챗GPT 앱의 '충전소 예약' 프로젝트(ev-booking 폴더)에서 GPT-6.1-Sol(medium)로 진행했습니다.

```text
TOSS_CLIENT_KEY=문서에 공개된 test_gck_docs_ 키
TOSS_SECRET_KEY=문서에 공개된 test_gsk_docs_ 키
```

## 02단계 결제 흐름 정리

```text
15장 실습을 시작할게. 예약금 결제를 토스페이먼츠 테스트 모드로 붙일 거야. 코드는 아직 만들지 말고, 공식 문서 보고 결제 흐름부터 정리해 줘. 금액 위변조나 중복 승인처럼 꼭 확인해야 할 것도 수용 기준이랑 연결해서 알려 줘.
```

## 03단계 남은 결정과 테스트

```text
남은 질문에 답할게. 임시 점유는 정확히 10분에 끝나고, 그 뒤에 승인이 오면 예약 없이 전액 환불해. 결제는 카드만 받고 DONE일 때만 완료로 봐. 환불이 실패하면 세 번까지 다시 해 보고, 안 되면 운영자 확인 필요로 둬. 금액 조작 거절이랑 승인 기한은 수용 기준에 추가해 줘. 그다음 결제 승인과 웹훅 테스트를 먼저 써 줘. 토스는 실제로 부르지 말고.
```

읽기 명령이 훅에 막혔을 때의 답:

```text
응, 하나씩 나눠서 확인하고 이어서 해 줘.
```

## 04단계 테스트 작성 스위치

```text
좋은 지적이야. 테스트를 써야 할 때만 내가 스위치를 켜는 걸로 하자. .codex/TEST_WRITING 파일이 있을 때만 tests/를 고칠 수 있게 가드를 바꾸고, 그 스위치랑 훅 파일은 네가 건드리지 못하게 막아 줘. 고치고 나서 다시 시험해 줘.
```

코덱스가 자기 보호 때문에 고치지 못한 guard.sh의 한 줄을 사람이 고친 뒤:

```text
말한 대로 한 줄 고쳤어. 다시 시험해 줘.
```

## 05단계 결제 테스트(터미널에서 `touch .codex/TEST_WRITING` 후)

```text
스위치 켰어. 이제 결제 승인이랑 웹훅 테스트를 써 줘.
```

## 06단계 루프 스크립트

```text
테스트는 확인하고 커밋했어. 구현은 루프로 돌릴 거야. 테스트가 다 통과할 때까지 codex exec로 고치게 하는 scripts/loop.sh를 만들어 줘. 최대 5바퀴, 20분까지만 돌리고, 같은 테스트가 3바퀴 연속 실패하거나 테스트 파일이 바뀌면 멈춰. 바퀴마다 기록도 남겨 줘. 실행은 아직 하지 마.
```

```text
지금은 구현 전이라 테스트가 실패하는 게 맞아. 스크립트만 만들고 끝내면 돼.
```

## 07·09단계 루프 실행

## 08단계 루프가 멈춘 원인 고치기

```text
루프가 1바퀴에서 BLOCKED로 멈췄어. artifacts/loops 기록 보고 원인 찾아서 고쳐 줘. 가드는 느슨하게 하지 말고, 가드에 걸리지 않게 일하는 쪽으로 고쳐 줘.
```

```text
응, 하나씩 읽어서 원인 찾고 고쳐 줘. 테스트 실패는 아직 구현 전이라 당연한 거니까 신경 쓰지 마.
```

## 10단계 노쇼·승계

```text
스위치 켰어. 노쇼 자동 취소랑 대기자 승계 테스트를 써 줘. 정확히 15분이 되는 순간, 결제 대기 10분, 30분 안 남았을 때처럼 경계가 되는 시각은 꼭 넣어 줘. 테스트만 쓰고 실패하는 걸 보여 준 다음 멈춰.
```

```text
이거 계속 반복되네. AGENTS.md에 tests 경로가 들어간 명령은 하나씩 따로 실행하라고 적어 두고, 테스트 작성 이어서 해 줘.
```

루프가 작업 설명을 받게 고치기:

```text
루프를 노쇼·승계 구현에도 쓰고 싶은데 지금은 결제 작업이 고정돼 있어. scripts/loop.sh "작업 설명"처럼 할 일을 받아서 돌게 고쳐 줘. 실행은 하지 마.
```

```text
응, 스크립트만 마무리해 줘. 그리고 이것도 계속 반복되니까 AGENTS.md에 적어 줘. Stop 훅이 테스트 실패를 알려 주는 건 막힌 게 아니야. 구현 중이면 계속 고치고, 구현하지 않는 작업이면 실패를 보고하고 끝내면 돼.
```

```sh
scripts/loop.sh "노쇼·승계 테스트(tests/rules/no-show.test.ts, succession.test.ts)는 내가 입력과 기대값을 확인하고 커밋했어. 이번 범위는 이 두 테스트를 통과시키는 src/rules의 순수 규칙 구현이고, 선행 작업은 이 테스트의 입력으로 대신해. 정책은 docs/prd.md와 docs/acceptance.md의 AC-11, AC-16을 따른다."
```

## 14단계 결제 시연 서버

```text
결제 화면을 실제로 보고 싶어. 토스 결제 위젯을 띄우는 작은 시연 서버를 만들어 줘. 주문 페이지에 충전소, 예약 시간, 예약금 3,000원을 보여 주고, 결제가 끝나면 우리 승인 코드로 처리해서 결과를 보여 주면 돼. 포트는 5180으로 해 줘.
```

```text
응, 그 구성으로 해. 충전소랑 시간은 원본에서 하나 골라 주고, 환불 실패는 '운영자 확인 필요'로 표시하면 돼. 시연용이니까 통합 테스트는 화면 확인으로 대신하고, 다 되면 띄워 줘.
```

```text
직접 해 봤어. 국민카드 고르고 3,000원 테스트 결제를 누르니 결제창은 열리는데 카드사 인증 화면이 하얗게 안 떠. 창을 닫으니 실패 화면은 나오는데 토스가 준 실패 코드랑 이유가 안 보여. 고칠 수 있는 건 고쳐 줘.
```

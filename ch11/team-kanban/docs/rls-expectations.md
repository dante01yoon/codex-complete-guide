# RLS 기대 권한과 실제 요청 테스트

Alice(owner), Bob(member), Carol(가입자지만 해당 보드 멤버 아님), anon(미로그인)을 사용한다. 테스트 기준은 Alice가 만들고 Bob을 등록한 테스트 전용 보드이다.

보드 삭제도 일반 보드 수정과 동일하게 멤버에게 허용한다. owner 전용 작업은 초대와 내보내기이다. 새 보드 생성은 기존 보드 접근과 별개이며 Carol도 자기 보드를 만들 수 있다.

추가 경계 테스트:

- 카드·컬럼을 자신이 참여하지 않은 다른 보드로 옮길 수 없다.
- 멤버는 보드 생성자를 바꾸거나 board_members 직접 쓰기로 자신을 owner로 승격할 수 없다.
- 초대한 멤버가 내보내진 뒤에는 기존 로그인 토큰으로도 해당 보드·컬럼·카드를 읽거나 변경할 수 없다.
- Alice/Bob은 move_kanban_card를 사용할 수 있고 Carol/anon은 사용할 수 없다.
- owner 자신을 내보낼 수 없다.

## 실행과 판정

`npm run test:rls -- before`와 `npm run test:rls -- after`로 동일한 테스트를 실행한다. Node 클라이언트가 Supabase Auth로 로그인한 뒤 실제 PostgREST·RPC HTTP 요청을 보낸다. 테스트 대상 요청에는 publishable 키와 각 사용자의 JWT만 사용한다. anon에는 로그인 세션을 사용하지 않는다.

관리 키는 테스트 fixture 구성·확인·정리에만 사용한다. 허용 테스트는 응답과 실제 저장 결과를 확인한다. 차단 테스트는 401/403·42501 또는 RLS의 빈 조회/수정 결과를 확인하고, 관리 클라이언트로 데이터가 변경되지 않았는지 검증한다. 성공 HTTP 응답만으로 UPDATE/DELETE 성공을 판정하지 않는다.

각 실행은 UUID가 포함된 별도 fixture 보드를 사용하고 종료 시 연쇄 삭제한다. 기존 보드와 Alice/Bob 멤버십을 변경하지 않는다. 비밀번호·JWT·관리 키는 출력하거나 결과 파일에 저장하지 않는다. 결과는 `docs/rls-results-before.json`, `docs/rls-results-after.json`에 보관한다.

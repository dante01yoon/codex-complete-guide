# 토스 결제 위젯 시연 서버 제안

상태: 사용자 구성 승인 후 구현 완료. 현재 검증 범위는 [payment-demo.md](payment-demo.md) 참조.
사용자는 원본 충전소·시간 선택, 환불 실패 시 운영자 확인 필요,
이번 시연 통합 테스트의 화면 확인 대체와 완료 후 서버 실행을 명시적으로 승인했다.

## 요청 범위

`http://localhost:5180`에서 충전소, 서울 시간 예약 구간, 예약금 3,000원과
토스 테스트 결제 위젯을 표시한다. 결제 인증 후 서버가 토스 승인 API를 호출하고,
검증된 응답을 기존 `src/rules/payment.ts` 공개 규칙에 전달하여 결과를 표시한다.
성공 URL에 도착했다는 이유만으로 결제 완료나 예약 확정을 표시하지 않는다.

## 추천 구성 — C-10 / T-01의 이번 시연 한정 결정 제안

- 기존 Node.js 24·TypeScript를 유지하고 Node HTTP 서버와 HTML·CSS·브라우저 JavaScript를 사용한다.
- 서버는 루프백의 5180 포트에만 연결한다. 외부 배포는 하지 않는다.
- 전체 예약 앱과 별개로 단일 시연 주문을 다룬다. 테스트 운전자 1명과 사전에 정한
  충전소·예약 구간을 사용한다. 실제 로그인·검색·대기·운영자 기능의 완료를 의미하지 않는다.
- 주문·점유·승인 처리 결과는 로컬 파일에 저장하고 같은 주문의 승인 처리를 직렬화한다.
  단일 운전자 시연이므로 로컬 브라우저들은 같은 주문을 공유하며 실제 로그인은 제공하지 않는다.
  재방문 결과 조회가 새 승인 요청을 만들지 않도록 한다.
- 정책 시계는 서버에서 한 곳으로 제공하고 서울 시간으로 표시한다.
  이번 화면에 시계 역행·초기화 기능은 넣지 않는다.
- 프로젝트 `.env`의 위젯용 테스트 키를 사용한다. 시크릿 키는 서버에만 두고
  키 값·인증 헤더·원문 결제 응답을 로그나 문서에 출력하지 않는다.

대안은 메모리 저장으로 서버 종료 시 주문 이력을 잃는 최소 서버,
또는 별도 프론트엔드 프레임워크를 도입하는 구성이다.
재방문·중복 처리 확인에 필요한 이력을 유지하면서 의존성 추가를 줄이는 위 구성을 추천한다.

## 결제 흐름 — US-05 / T-15·16·17·19·20의 시연 부분

1. 서버 저장 주문을 기준으로 주문 정보와 테스트 결제·환불 조건을 표시한다(AC-05-1).
2. 결제 진입 시 점유 기한을 저장하고 토스 위젯을 연결한다(AC-05-2·3).
3. 서버는 반환된 주문 ID·금액을 `validatePaymentApprovalRequest`로 확인한 뒤 승인한다(AC-05-7).
4. 실제 승인 응답을 정규화하고 `reduceVerifiedPaymentApproval`에 전달한다.
   주문·금액·통화·카드·DONE·기한·중복 규칙을 재사용한다(AC-05-4·8·9).
5. 결과 화면은 결제 완료와 시연 예약 확정, 승인 실패, 환불 필요·완료·실패를 구분한다.
   환불 효과 요청 자체를 환불 완료로 표시하지 않는다(AC-05-5·6, AC-06-2).

웹훅 실수신과 T-51, 전체 예약 자격·권한·동시 예약 서비스는 별도 작업이다.
기존 순수 규칙의 입력 전제인 자격·소유자·자리 검사를 임의로 통과시키는 방식으로
전체 예약 서비스의 확정 결과를 주장하지 않는다.

## 사용자 답변 (확정된 시연 범위)

아래 질문에는 구성 승인, 원본 자동 선택, 환불 실패 시 운영자 확인 필요로 답변했다.
통합 테스트는 이번 시연에 한해 화면 확인으로 대신하도록 명시했다.

1. C-10: 위 구성과 단일 주문 시연 범위를 사용할 것인가?
2. C-05·C-09: 시연할 충전소·예약 구간·시계 기준을 지정할 것인가,
   아니면 원본 후보와 충돌 없는 미래 60분 구간을 제안받을 것인가?
3. C-07 / AC-05-10: 늦은 승인 보상 환불 실패 시 최초 실패 뒤 추가 3회 재시도인가,
   최초를 포함해 총 3회인가? 재시도 간격과 응답 불명 처리도 확정해야 한다.
   이번 시연에서 자동 재시도를 보류하고 환불 요청·결과 및 수동 확인 필요를 보여 주는
   제한 범위를 선택하려면 사용자에게 별도로 확인한다.

## 다음 관문과 검증

위 답변을 관련 PRD·AC·작업 목록에 시연 범위로 기록했다.
사용자 직접 지시에 따라 이번 HTTP 통합 검증은 브라우저 화면 확인으로 대체했다.
기존 테스트·훅·헌법 전역 설정은 변경하지 않았다.

- 정적 코드·키 종류 확인: PASS. 테스트 키 값은 기록하지 않았다.
- 시연 서버 구현·실행: PASS.
- 브라우저 위젯: PASS. 통합 자동 테스트: NOT_RUN (사용자 지정 화면 확인 대체).
- 실제 테스트 승인·환불 완료: NOT_RUN. 카드 인증 외부 연결 제한은 현재 검증 기록 참조.

# 16장 에이전트 작업 기록 화면

실행: `npm run demo:agents`

접속: http://127.0.0.1:5186 . 루프백에서만 제공하는 읽기 전용 도구다.
다른 포트는 `GRAPH_VIEW_PORT`로 지정한다. 종료는 실행 터미널에서 Ctrl-C.
예약·결제 기능, 승인 파일, 원본 충전소 데이터에는 접근하거나 쓰지 않는다.

## 원본과 해석

- `docs/agents.md`의 Mermaid 블록에서 노드 11개·화살표 16개를 읽는다. 그래프는 실제 실행 로그가 아니라 협업 절차다.
- `mcp-booking-validation.md`와 `mcp-server-validation.md`의 명시된 진행 기록을 각각 표시한다. 근거 문장과 줄 번호를 유지한다. 시각의 시간대가 없으면 그대로 미기록으로 안내한다.
- 선택한 인계는 기록의 역할·단계에 대응하는 화살표를 강조한다. 역할 간 인계가 명시되지 않은 재검증·조회 차단 기록은 화살표를 강조하지 않는다.
- `acceptance.md`의 AC 제목 87개를 기준으로 표를 만든다. MCP 서버 문서의 AC별 결과 표, 순수 규칙 문서의 완료 범위, 결제 테스트 확인 자료의 사용자 확인 후 실행 상태, 단일 주문 시연 결과를 읽는다.
- MCP 서버는 순수 규칙 작업을 명시적으로 잇는 후속 작업이므로 같은 MCP 흐름의 결과를 우선한다. 선행 결과는 펼쳐서 볼 수 있다. 결제 테스트와 화면 시연은 별도 흐름으로 표시하고 서로의 날짜 순서를 추정하지 않는다.
- 금액·조건·기대 결과·정적 타입 PASS·테스트 개수로 기능 PASS를 만들지 않는다. 결과가 없는 AC는 **기록 없음**이며 NOT_RUN과 다르다. 부분 PASS는 해당 범위에 한정한다.
- 단일 주문 시연의 AC 연결은 `acceptance.md`의 승인된 시연 확인 범위를 근거로 삼는다. 실제 토스 승인·환불 완료는 NOT_RUN을 유지한다.
- 원본 링크는 현재 문서의 해당 줄을 강조한다. 입력 문장은 텍스트로 렌더링한다. 파일 수정 시 화면 새로고침으로 다시 읽으며, 핵심 근거가 사라지면 임의로 채우지 않고 오류를 표시한다.

추출은 알려진 문서 구조와 명시된 근거에 한정하며, 자유 문장 전체를 자동으로 해석한 결과가 아니다.
새 인계 문서나 다른 구조의 AC 결과를 추가하면 추출 계약도 함께 갱신해야 한다.

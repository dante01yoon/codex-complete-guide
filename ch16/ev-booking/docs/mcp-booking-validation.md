기준 커밋: `840a01ab606d11231a49eaa730228f185e3cbbff`.
범위: [계획](mcp-booking-plan.md)의 공개 함수 5개와 승인된 규칙 테스트 34개.
실제 MCP 등록·승인 파일 생성 명령·파일 I/O·결제 URL·토스 연결은 이번 순수 규칙 검증에 포함되지 않는다.

## 사용자 확인과 인계

- 사용자가 테스트를 확인하고, 스위치를 끈 뒤 커밋한 상태에서 구현·리뷰를 요청했다.
- 사용자 추가 지시: 해시 대신 `git diff`로 테스트 불변을 확인한다. 같은 사례 3연속 실패의 집계는 구현을 시작한 뒤부터 적용하며 구현 전 Red 실패는 제외한다.
- 리뷰에서 P1이 나오면 수정과 재리뷰는 최대 2회이다. 테스트 변경이 필요하거나 실제 도구 차단이 발생하면 별도 중단 기준을 따른다.
- 테스트 담당이 실행한 `git diff HEAD -- tests/rules/mcp-booking.test.ts`: 종료 코드 0, 빈 diff. 승인된 테스트 불변 확인.
- 승인 후 Stop 훅(08:05:48)이 실행한 `npm run test:rules`: 신규 34개 FAIL, 기존 156개 PASS. 공개 함수 5개가 없어 `undefined`를 함수로 기대한 assertion이 실패했다. 같은 훅의 타입 검사 PASS.
- 위 실패는 실제 미구현 Red 증거이며 파일 I/O·MCP·토스 통합의 실패 증거가 아니다.

## 진행 상태

- 구현 담당: `src/rules/mcp-booking.ts`에 공개 순수 함수 5개 및 타입을 추가하고 `src/rules/index.ts`에서 export했다. 기존 겹침 판정을 재사용한다.
- 구현 후 신규 검사: `npx vitest run tests/rules/mcp-booking.test.ts`, 종료 코드 0, 34/34 PASS(구현 담당 실행).
- 부모 재검증: `npm run test:rules`, 종료 코드 0, 9파일 190/190 PASS(08:11:47). `npm run typecheck`와 `git diff --check`도 종료 코드 0, PASS.
- 부모의 `git diff HEAD -- tests/rules/mcp-booking.test.ts` 역시 빈 diff였다. 테스트·설정·가드·승인 폴더를 에이전트가 변경하지 않았다.
- GPT-6-Astra 읽기 전용 리뷰: 완료. 사용자 승인 후 `cat`으로 승인 테스트 34개와 신규 소스·export를 직접 대조했으며 합의된 순수 함수 범위에서 확인된 P0~P3 지적이 없었다. 리뷰어가 검증 명령을 재실행한 것은 아니며 위 부모·구현 담당의 실행 증거를 검토했다.
- 조회 차단 기록: `nl -ba` 테스트 읽기가 가드에 차단되어 중단했으나 사용자가 `cat`·`rg` 조회로 재개하도록 명시 승인했다. 가드 변경이나 승인 없는 우회는 하지 않았다.
- 구현 후 테스트 실패: 0회.
- P1 수정·재리뷰: 0/2회.
- 브라우저·실제 MCP·승인 명령·토스 연결: NOT_RUN.

## 완료 범위와 남은 제한

- AC-18-1~5·7의 계획에 명시한 순수 판정 부분을 구현·검증했다. 전체 AC, 실제 MCP 도구 세 개, 원자적 점유 저장, 승인 파일 생성·보호, 실제 결제 URL 사용 차단의 완료를 의미하지 않는다.
- C-12의 정확히 1000m 입력은 현재 합의된 함수 계약 밖이라는 오류로 드러낸다. 이는 포함·제외 정책을 확정한 것이 아니며 실제 adapter에 연결하기 전에 합의가 필요하다.
- C-12~15의 미정 통합 정책은 유지한다. 승인 파일 context는 신뢰된 adapter가 읽어 전달해야 하며 모델 인수로 대체하지 않는다.
- P1 지적이 없어 수정·재리뷰 없이 종료했다. 제품 소스 변경은 신규 규칙 파일과 공개 export에 한정되며 승인된 테스트는 그대로다.

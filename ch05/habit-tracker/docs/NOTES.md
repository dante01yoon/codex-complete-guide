# 습관 트래커 인계 노트

작성일: 2026-10-03 (America/New_York). 이 채팅의 합의와 실제 작업 결과를 정리했다. 다음 채팅에서는 이 문서를 출발점으로 삼되 코드·브라우저·권한·서버의 현재 상태는 다시 확인한다.

## 현재 상태와 다음 작업

- 앱 이름은 **하루 한 칸**. 기본 습관 트래커와 다크 모드 구현을 마쳤다.
- 마지막 자동 테스트 결과는 **23개 PASS, 실패 0개**다. 모든 실제 브라우저 완성 기준이 검증된 것은 아니다.
- 다음으로 할 일은 아래 ‘남은 검증’을 수행하고 발견한 문제를 수정하는 것이다. 추가 기능이나 배포는 아직 요청되지 않았다.
- 이번 요청은 인계 문서 작성이다. 앱 코드는 이번 작업에서 변경하지 않았다.

## 사용자와 확정한 결정

### 앱의 목적과 범위

- 혼자, 한 브라우저에서 사용하는 한국어 웹앱이다. 로그인 없이 브라우저에 저장한다.
- 습관은 매일 실천하며 완료·미완료만 기록한다. 요일 선택과 횟수·분량 목표는 제외했다.
- 이름 추가·수정·삭제를 지원한다. 삭제 전 확인하며 해당 습관의 기록도 함께 삭제한다.
- 등록일부터 오늘까지 체크·취소할 수 있다. 등록 전과 미래 날짜는 수정할 수 없다.
- 로그인, 기기 간 동기화, 공개 배포, 백업·복원, 메모, 보관 기능은 현재 범위 밖이다.
- 로컬에서 모바일·PC의 주요 기능을 실제 브라우저로 검증하는 것이 완성 기준이다.

### 연속 실천 일수 — 핵심 기능

- 오늘 완료했다면 오늘부터 과거로 연속 완료 날짜를 센다.
- 오늘 미완료라면 어제까지의 연속 실천 일수를 유지한다. 오늘을 아직 체크하지 않았다고 바로 0일로 만들지 않는다.
- 오늘과 어제 모두 미완료면 0일이다. 중간에 빠진 날짜를 만나면 계산을 멈춘다.
- 과거 체크를 수정하면 즉시 다시 계산한다. 등록일 이전 기록은 계산에 포함하지 않는다.
- 예: 10월 1·2일 완료, 3일 미완료 → 2일. 3일까지 완료 → 3일. 2일 체크 취소, 3일 완료 → 1일.

### 최근 12주 히트맵 — 핵심 기능

- 전체 습관의 합산 히트맵 대신 **습관별** 히트맵을 제공한다.
- 구현은 월요일 시작, 이번 주를 포함한 12개 달력 주다. 12열 × 7행, 총 84칸이며 단순히 오늘까지의 최근 84일과는 다르다.
- 완료·미완료·등록 전·미래 날짜를 구분하고 오늘은 테두리로 표시한다. 미래·등록 전 칸은 비활성화한다.
- 유효한 칸을 클릭하면 체크·취소한다. 12주보다 오래된 기록은 ‘지난 기록’ 날짜 입력으로 수정할 수 있다.

### 날짜와 저장

- 기기의 현지 날짜를 사용한다. 날짜 키는 `YYYY-MM-DD`다.
- 현지 오늘 날짜를 만든 뒤 달력 날짜 연산에만 UTC를 사용한다. 서머타임 때문에 하루 계산이 어긋나지 않게 했다.
- 열린 화면은 15초마다, 창 포커스 복귀 시, 다시 보이는 시점에 날짜 변경을 확인한다.
- 새로고침과 브라우저 재실행 후 기록 유지가 요구사항이다. 실제 완전 재실행 검증은 아직 남아 있다.
- 기록은 같은 브라우저·주소·포트에서만 유지된다. 시크릿 모드, 브라우저 데이터 삭제, 다른 기기로의 동기화는 보장하지 않는다.

### 다크 모드

- 사용자가 추천안을 모두 승인했다: **시스템·라이트·다크 3가지**, 최초에는 시스템 설정, 브라우저에 선택 저장, 녹색 포인트를 유지한 짙은 녹회색, 헤더의 선택 메뉴.
- 수동 라이트·다크는 시스템 설정보다 우선한다. 시스템 선택 중에는 운영체제 테마 변경 이벤트를 반영한다.
- 테마 설정은 습관 데이터와 별도 저장 키를 사용한다. 저장 불가 시에도 현재 화면의 전환은 가능하며 한국어 안내를 표시한다.
- 테마 스크립트를 스타일시트보다 먼저 실행해 초기 깜빡임을 줄인다. 색상은 역할별 CSS 변수로 관리한다.
- 카드·입력·버튼·대화상자·오류·히트맵·범례·포커스까지 두 테마를 적용한다. 기존 레이아웃과 날짜 계산은 유지한다.
- 구현 중 재방문 시 실제 테마와 선택 메뉴가 불일치하는 문제를 발견했다. DOM 준비 후 다시 테마를 적용하도록 수정했고 테스트도 통과했다.

## 반드시 지킬 작업 규칙

1. 화면 문구와 설명은 한국어로 쓴다.
2. 외부 라이브러리·프레임워크·CDN 없이 HTML, CSS, JavaScript만 쓴다. 테스트와 로컬 서버도 Node.js 내장 기능만 사용한다.
3. 날짜 계산은 DOM/화면 코드에서 분리하고 `node --test`로 검증한다.
4. 작업 후 자동 검사와 실제 브라우저 검증을 구분한다. **PASS / FAIL / NOT_RUN / BLOCKED**와 실행 명령·미확인 사유를 보고한다. 실행하지 않은 검사를 통과했다고 쓰지 않는다.
5. 사용자 데이터를 지우지 않는다. 테스트 기록은 별도 브라우저 환경 또는 명확한 검증용 습관으로 만들고, 자신이 만든 기록만 정리한다.

프로젝트 루트 `AGENTS.md`에 1~4번 규칙과 앱 요구사항이 있다. 문서에 있던 일회성 ‘현재 작업 제한’은 사용자 요청으로 이미 삭제했다. 앱 구현을 막는 제한으로 다시 추가하지 않는다. 사용자 제공 전역 지침 중 Second Brain·영상 제작 절차는 영상·콘텐츠 제작 요청이 있을 때 적용한다.

## 실행 방법과 코드 지도

프로젝트 루트: `~/Documents/habit-tracker`

```sh
cd ~/Documents/habit-tracker
node server.mjs
```

접속: `http://127.0.0.1:5173/`. Node.js 20 이상, 패키지 설치 불필요. HTML 파일을 직접 열면 모듈 로딩 문제가 있으므로 서버로 실행한다. 서버 실행 여부는 다음 채팅에서 확인한다. 포트가 사용 중이면 기존 프로세스와 실행 경로부터 확인하고 임의로 종료하지 않는다. 서버 파일 제공 목록을 바꿨다면 서버 재시작이 필요하다.

| 파일 (프로젝트 루트 기준) | 역할 |
| --- | --- |
| `index.html` | 한국어 화면, 헤더 테마 선택, 수정·삭제 대화상자. `theme.js`를 CSS보다 먼저 일반 스크립트로 로드 |
| `styles.css` | 공통 레이아웃, 반응형, 라이트 기본 변수와 `[data-theme="dark"]` 변수 |
| `app.mjs` | 화면 렌더링, 습관 CRUD, 체크, 날짜 변경 감지, 저장 및 다른 탭 변경 반영 |
| `dates.mjs` | `localDateKey`, `parseDate`, `addDays`, `canRecord`, `streak`, `heatmapWeeks`, `displayDate` |
| `model.mjs` | 저장 데이터 검증·복원, 체크 변경, 습관 저장 키 |
| `theme.js` | 초기 테마 적용, 선택·저장·시스템 변경·다른 탭 이벤트, 저장 실패 안내 |
| `dates.test.mjs` | 날짜·연속 일수·히트맵·저장 로직의 15개 테스트 |
| `theme.test.mjs` | 테마 동작·저장 실패·데이터 보존·색상 대비의 8개 테스트 |
| `server.mjs` | 127.0.0.1의 정적 서버. 제공 파일은 허용 목록으로 제한하므로 새 브라우저 파일 추가 시 목록 확인 |
| `README.md` | 실행·사용·테스트 안내 |
| `VERIFICATION.md` | 최초 앱 검증과 다크 모드 추가 검증을 구분한 상세 기록 |

`theme.test.mjs`는 실제 테마 스크립트를 Node.js VM의 제어된 DOM·저장소·시스템 이벤트로 검사한다. 실제 브라우저 테스트로 오해하지 않는다. `.playwright-mcp/`의 검증 스크린샷·스냅샷은 Git에서 제외돼 있어 다음 환경에 없을 수 있다.

### 저장 인터페이스

- 습관 키: `habit-tracker.v1`
- 값: JSON `{ version: 1, habits: [{ id, name, createdAt, records }] }`. `id`는 UUID, 이름은 최대 60자, `createdAt`는 현지 등록일, `records`는 완료 날짜 키 배열이다. 중복 기록은 제거해 정렬한다.
- 테마 키: `habit-tracker.theme.v1`. 문자열 `system`, `light`, `dark` 중 하나다. 미설정·잘못된 값은 시스템으로 처리한다.
- 손상된 습관 데이터는 덮어쓰지 않고 편집을 중단한다. 저장 실패 시 습관 변경은 적용하지 않는다.

## 남은 검증과 재개 순서

다음 목록은 미완료 상태다. 새 환경에서 권한 상태를 확인하고 허용된 방법으로 검증한다. 과거 차단이 현재도 이어진다고 단정하지 않는다.

1. **BLOCKED 이력:** 키보드로 테마 선택·포커스·대화상자 닫기, 실제 라이트 재전환. 거부 사유는 `MCP tool call requires approval, but approval policy is never`. 거부된 검사를 우회해서 실행하지 않았다.
2. **NOT_RUN:** 변경 후 라이트 모드의 320px·390px·1440px 화면 전체 확인. 두 테마에서 긴 이름, 입력, 히트맵, 대화상자도 확인한다.
3. **NOT_RUN:** 실제 시스템 테마 변경 시 시스템 선택에만 반영되는지 확인. 수동 선택은 그대로 유지돼야 한다.
4. **NOT_RUN:** 브라우저 완전 종료·재실행 후 습관과 테마 복원. 페이지 재접속만 확인한 상태다. 같은 주소·포트로 확인한다.
5. **NOT_RUN:** 실제 브라우저에서 과거 기록을 수정해 연속 일수·히트맵이 함께 갱신되는지, 오늘 체크 취소·이름 저장·삭제 취소가 정상인지 확인. 자동 계산 테스트와 대화상자 열기만으로 통과 처리하지 않는다.
6. **NOT_RUN:** 실제 현지 자정 전환 또는 제어된 브라우저 시계로 오늘 날짜·오늘 체크·연속 일수 갱신 확인. 등록일·월말·연말 경계도 확인한다.
7. **NOT_RUN:** 실제 브라우저 저장 차단·손상 상태에서 데이터 보호와 안내, 테마 전환 유지 확인. 현재는 자동 테스트와 코드로만 검증했다.
8. **NOT_RUN:** 첫 프레임의 잘못된 테마 깜빡임 확인. 초기 스크립트 순서 자동 검사는 통과했지만 첫 프레임 캡처는 하지 않았다.

재개 시 권장 순서: 작업 트리와 서버 확인 → `node --test`로 현재 기준선 확인 → 위 브라우저 검사 → 발견한 문제만 수정 → 관련 검사 재실행 → `VERIFICATION.md`와 이 노트 갱신. 사용자에게 실제 실행 결과와 남은 항목을 구분해 보고한다.

이 문서 작성 시 `git status --short`는 비어 있었다. 최근 커밋은 `6baf8c7`(다크 모드 추가), `93b7b0d`(습관 트래커 구현), `4bb72e6`(AGENTS.md 작성)이다. 인계 문서는 이번 요청으로 추가하며 커밋·푸시를 따로 요청받지는 않았다. 다음 작업에서 현재 Git 상태를 다시 확인한다.

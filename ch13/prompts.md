## 13.4 연습 프로젝트(tdd-practice)에서 보낸 요청

1. AGENTS.md에 '## 테스트' 절을 만들고 다음 규칙을 넣어 줘. 테스트 실행은 npm test. 새 기능은 수용 기준(AC 번호)마다 실패하는 테스트를 먼저 쓰고, 실행해서 실패를 확인한 뒤 구현한다. 테스트 이름에 AC 번호를 넣는다. 구현 단계에서는 tests/ 폴더의 파일을 고치지 않는다. 테스트가 틀렸다고 생각되면 고치지 말고 이유를 보고한다. 완료를 보고할 때는 실행한 테스트 명령과 통과·실패 개수를 함께 적는다. 다 넣었으면 커밋해 줘.
2. docs/acceptance.md의 AC-1부터 AC-5까지를 Vitest 테스트로 만들어 줘. 파일은 tests/fee.test.ts로 하고 테스트 이름에 AC 번호를 넣어. 구현은 하지 마. src/fee.ts에는 '아직 구현하지 않음' 오류를 던지는 빈 함수만 만들어. 그리고 테스트를 실행해서 모두 실패하는지, 실패 이유가 무엇인지 보여 줘.
3. 좋아. 테스트 파일과 src/fee.ts를 커밋해 줘. 커밋 메시지는 'AC-1~AC-5 실패하는 테스트 추가'로 하고, 커밋 해시와 커밋된 파일 목록을 보여 줘.
4. (새 채팅) /goal tests/fee.test.ts의 테스트가 모두 통과한다. npm test 결과로 확인한다. tests/ 폴더의 파일은 수정하지 않는다. 구현은 src/fee.ts에 한다.
5. 테스트를 커밋한 뒤로 tests/ 폴더가 바뀌었는지 git diff --stat HEAD -- tests/ 결과를 그대로 보여 줘. 그리고 테스트를 이름별 통과 여부가 보이는 자세한 형식으로 실행해서 목록을 보여 줘.
6. 구현을 먼저 커밋해 줘. 그다음 테스트를 모두 통과하는 상태를 유지하면서 src/fee.ts를 읽기 쉽게 정리해 줘. 정리한 뒤 테스트를 다시 실행하고, 무엇을 바꿨는지와 통과·실패 개수를 알려 줘.
7. $verification-before-completion 리팩터가 끝났다고 보고해도 되는지 확인해 줘. 확인이 끝나면 정리한 내용을 커밋해 줘.
8. (새 채팅) $brainstorming 충전 요금에 심야 시간대 할인을 추가하고 싶어.

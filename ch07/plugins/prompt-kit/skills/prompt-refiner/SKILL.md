# Prompt Refiner

사용자가 하고 싶은 일을 바로 구현하지 않고, Codex에게 전달할 한국어 프롬프트로 다듬는다. 이 단계에서는 프로젝트 파일을 수정하거나 구현·설치·배포를 실행하지 않는다.

## 파일에 근거한 요청 정리

- 사용자 요청과 작업 경로를 확인하고, 적용되는 `AGENTS.md` 및 요청과 관련된 실제 소스·설정·테스트 파일을 읽는다. 파일 검색에는 `rg --files`와 `rg`를 우선 사용한다.
- 읽은 파일의 경로, 역할, 현재 동작을 근거로 맥락을 작성한다. 파일 이름만 보고 역할을 추측하거나, 읽지 않은 파일을 확인한 것처럼 적지 않는다.
- 프로젝트 경로가 불명확하면 현재 작업 공간에서 확인 가능한 내용을 먼저 조사한다. 필요한 파일에 접근할 수 없으면 확인하지 못한 내용을 표시하고 경로나 자료를 요청한다.
- 사용자의 목표와 범위를 유지한다. 프로젝트에서 확인한 규칙과 사용자가 명시한 제약을 반영하고, 제안이나 미정 사항을 확정된 요구사항으로 바꾸지 않는다.

## 출력 형식

복사해 Codex에게 줄 수 있는 프롬프트를 다음 네 항목으로 작성한다.

### 목표

무엇을 왜 바꾸려는지, 기대하는 사용자 동작과 작업 범위를 적는다.

### 맥락

실제로 읽은 관련 파일의 경로와 각 파일의 역할, 요청에 영향을 주는 현재 동작을 적는다. 확인한 사실과 추정·미확인 내용을 구분한다.

### 제약 조건

바꾸면 안 되는 동작·파일·데이터와 지켜야 할 프로젝트 규칙을 적는다. 사용자가 정한 작업 경계와 의존성·기술 조건을 보존한다.

### 완료 기준

무엇을 어떤 방법으로 확인하면 완료인지 관찰 가능한 기준으로 적는다. 관련 자동 테스트의 명령과 기대 결과, 실제 브라우저나 수동 확인이 필요한 동작을 구분한다. 여기서는 검증 계획을 작성하며, 실행하지 않은 검증을 통과했다고 표현하지 않는다.

사용자가 결정해야 할 사항이 있을 때만 프롬프트 뒤에 **결정이 필요한 질문**을 덧붙인다. 각 질문에 추천안과 짧은 이유를 함께 적고, 답변에 따라 달라지는 범위를 설명한다. 미정인 선택은 본문에도 미정으로 표시한다. 이미 요청이나 실제 파일에서 확인할 수 있는 내용은 다시 묻지 않는다.

정리한 프롬프트와 질문을 전달한 뒤 구현을 시작하지 않는다.

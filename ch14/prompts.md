# 14장 요청 프롬프트

챗GPT 앱의 '충전소 예약' 프로젝트(ev-booking 폴더)에서 GPT-6.1-Sol(medium)로 진행했습니다. 사람이 정해야 하는 것만 적고, 나머지는 AGENTS.md와 docs 문서, 훅에 맡겼습니다.

## 01단계 도메인 규칙

```text
14장 실습을 시작할게. AGENTS.md에 예약·결제 도메인 규칙을 정리해 줘. 금액은 원 단위 정수, 시간은 서울 기준이고, 규칙 코드는 src/rules에만 둬. 결제는 토스페이먼츠 테스트 키만 써. 자세한 정책은 docs 문서를 가리키게 하고 AGENTS.md는 짧게 유지해 줘.
```

## 02단계 훅 만들기

```text
이제 하네스를 만들자. .codex 폴더에 guard.sh와 verify.sh를 만들어 줘. guard.sh는 tests/ 파일을 바꾸려는 명령이나 패치, 그리고 실제 결제 키(live_)가 들어간 입력을 막아 줘. verify.sh는 일을 끝내기 전에 테스트와 타입 검사를 돌려서, 실패하면 한 번만 더 고치게 해. 만든 뒤 막을 것과 통과시킬 것을 직접 넣어 시험해 보고, 훅 신뢰는 내가 할게.
```

## 04단계 훅 시험

```text
환불 정책이 바뀌었다고 가정하자. tests/rules/refund.test.ts에서 AC-07-2의 기대 환불 금액 1,500원을 1,000원으로 바꿔 줘
```

```text
결제 연동을 미리 준비하자. src/payments/config.ts 파일을 만들고 시크릿 키 상수를 live_sk_FAKE0000000000 값으로 넣어 줘
```

```text
Stop 훅이 동작하는지 실험해 보자. src/rules/refund.ts에서 120분 경계 비교를 '이상'에서 '초과'로 바꿔 줘. 테스트는 실행하지 말고 바꾸기만 해
```

정책 변경 요청(헌법과 훅이 부딪히는 상황):

```text
환불 정책이 바뀌었어. 시작 30분~2시간 전에 취소하면 1,500원 대신 1,200원을 돌려주도록 바꿔 줘
```

## 05단계 막혔을 때의 처리

```text
AGENTS.md에 막혔을 때 어떻게 할지 적어 줘. 훅에 막히면 돌아가지 말고 멈춰서 나한테 물어보고, 정책 때문에 테스트를 바꿔야 하면 직접 고치지 말고 무엇을 바꿔야 하는지 정리해 줘. 같은 테스트가 세 번 연속 실패해도 멈춰. 지금까지 만든 하네스 구성은 docs/harness.md에 표로 정리해 줘.
```

## 06단계 하네스 확인 화면

```text
하네스가 뭘 지키는지 눈으로 볼 수 있는 확인 화면을 demo 폴더에 만들어 줘. 시점별 환불 금액, 테스트 결과, tests 폴더가 바뀌었는지를 보여 주면 돼. 다른 폴더에도 복사해서 쓸 거고 포트는 4174로 해 줘. 다 되면 커밋하고 띄워 줘.
```

읽기 명령이 훅에 막혀 멈췄을 때의 답:

```text
응, 읽기만 하는 명령이니까 훅은 그대로 두고 tests 경로가 들어간 건 명령을 하나씩 나눠서 실행해. 이어서 끝내 줘.
```

헌법대로 검증 테스트를 먼저 쓰고 확인을 요청했을 때의 답:

```text
확인했어. 그대로 진행해 줘.
```

## 07단계 하네스 있음·없음 비교

하네스 없음 폴더의 `demo/config.mjs`에서 `port`를 4175로 바꾸고 `node demo/server.mjs`로 띄운 뒤, 두 프로젝트에 같은 요청을 보냅니다.

```text
환불 정책이 바뀌었어. 시작 30분 전부터 120분 전 사이에 취소하면 1,500원 대신 1,000원을 돌려주도록 바꿔 줘.
```

하네스 있음 프로젝트에서 읽기 명령이 막혔을 때의 답:

```text
응, 명령을 하나씩 나눠서 확인해 줘.
```

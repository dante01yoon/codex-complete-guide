# Research: 예약 겹침과 커넥터 호환 규칙

작성일: 2026-10-05. 문서 조사와 설계 결정이며 기능 실행 결과가 아니다.

## 1. 기술 구성과 테스트 환경

- **Decision**: C-10의 Node.js 24·TypeScript·Vitest를 사용하고 ESM·strict 타입 검사·Node 테스트 환경으로 계획한다.
- **Rationale**: [Vitest 가이드](https://vitest.dev/guide/)의 현재 요구 조건은 Node 22.12 이상이다.
  Node 24는 이 조건을 충족한다. [환경 문서](https://vitest.dev/guide/environment.html)상
  기본 node 환경은 순수 함수에 적합하므로 DOM 모사·브라우저는 필요 없다.
  [Node 24 TypeScript 문서](https://nodejs.org/docs/latest-v24.x/api/typescript.html)에 따르면
  타입 제거 실행은 타입 검사와 tsconfig 적용을 대신하지 않는다.
  [TypeScript strict](https://www.typescriptlang.org/tsconfig/strict)의 엄격 검사와
  `tsc --noEmit`을 테스트와 분리한다.
- **Alternatives considered**: Node 내장 테스트만 사용하는 방식은 사용자 지정 Vitest와 다르므로 채택하지 않는다.
  jsdom·브라우저 테스트는 화면 없는 범위에 필요 없다. 프레임워크·번들 앱 골격을 추가하지 않는다.
- **Version handling**: 정확한 도구 버전은 후속 테스트 환경 준비 시 Node 24 지원을 확인해 잠금 파일로 고정한다.
  이 문서에서 임의의 최신 패키지 버전을 확정하거나 설치하지 않는다.

## 2. 시간 표현과 겹침

- **Decision**: 정상 구간은 유한 정수 epoch milliseconds로 전달받고 `[시작, 종료)`로 비교한다.
  겹침 판정식은 `a.startMs < b.endMs && b.startMs < a.endMs`이다.
- **Rationale**: PRD 4.2.1·AC-04-3의 같은 경계 허용을 직접 표현한다.
  서울 오프셋을 명시한 픽스처를 쓰면 호스트 시간대에 결과가 의존하지 않는다.
- **Alternatives considered**: 문자열 사전순 비교·암묵적인 로컬 Date 파싱·현재 시각 조회는 불필요한 해석을 만든다.
  날짜 라이브러리는 구간 비교만 하는 이번 범위에 필요 없다.
- **Boundary**: 점유 유효 여부는 입력 전제이다. 10분 만료 경계와 시연 시계 처리는 C-04·C-09 영역이다.

## 3. 충전기와 커넥터

- **Decision**: 식별자 두 필드를 각각 비교하고, 알려진 6종·11코드만 리터럴 타입으로 받는다.
  지원 대응은 PRD 1.4·AC-02-7의 정적 표를 따른다.
- **Rationale**: 원본 `statId + chgerId` 구분과 사용자 직접 선택 정책을 보존한다.
  복합 타입·NACS와 버스전용 타입을 임의로 합치지 않는다.
- **Alternatives considered**: 차종 자동 판별·코드 숫자 변환·문자열 이름 부분 일치·어댑터 추정은 제외한다.
- **Boundary**: 미선택·미정의 코드·선택 변경·버스 자격의 서비스 실패 처리는 AC-02-9/C-11에 남긴다.

## 4. 순수 판정과 기존 제한

- **Decision**: 구간 겹침, 충전기별 겹침, 커넥터 지원, 결합 결과를 작은 함수로 분리한다.
  결합 결과에 각 조건과 호출자가 전달한 기존 자격 결과를 함께 남긴다.
- **Rationale**: 화면·저장소를 제외한 사용자 요청 안에서 독립 검증이 가능하고,
  AC-02-8의 기존 제한을 참으로 덮어쓰지 않는다.
- **Alternatives considered**: DB에서 원자적 점유를 만들거나 UI 문구를 직접 출력하는 서비스는 범위 밖이다.
  실패 사유 하나를 우선 선택하는 방식은 문서가 정하지 않은 표시 순서를 만들므로 채택하지 않는다.
- **Limit**: 스냅샷 판정은 동시성 보호가 아니다. AC-04-4, T-13 원자적 점유와 T-17 예약 확정의 완료 근거가 아니다.

## 5. 테스트 우선과 증거

- **Decision**: 테스트 작성 → 구체적 파일에 대한 사용자 확인 → 실제 기능 실패 확인 → 구현 순서를 따른다.
  테스트를 실행할 최소 선언·미구현 진입점이 필요하면 테스트 준비 범위에서 마련하고
  기능 로직은 넣지 않는다. import 실패·도구 오류는 Red로 인정하지 않는다.
- **Rationale**: 헌법 III의 NON-NEGOTIABLE 절차를 충족하려면 기대 결과에 도달하지 못한
  대상 함수 호출의 실패가 필요하다. 실제 테스트 확인 전의 계획 승인은 승인 증거가 아니다.
- **Alternatives considered**: 구현 후 테스트, 구현 표를 가져와 기대값 생성, 실패할 때 테스트 완화,
  설정으로 검사 제외는 금지한다.
- **Evidence**: AC·S별 결과, 명령·시간·실패 이유, 승인한 테스트 파일 목록·해시,
  구현 후 동일 테스트 해시와 실행 결과를 후속 작업 완료 기록에 남긴다.

## Resolution status

사용자의 이번 범위 지정으로 이 기능의 기술 구성은 계획할 수 있으나 전체 C-10/T-01 완료가 아니다.

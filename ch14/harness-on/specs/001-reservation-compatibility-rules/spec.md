# Feature Specification: 예약 겹침과 커넥터 호환 규칙

**Feature Branch**: `main` (명세 작성 시점의 기존 브랜치; 생성 훅 없음)

**Created**: 2026-10-05

**Status**: Draft — 명세 품질 검토 완료, 기능 검증 NOT_RUN

**Input**: User description: "같은 충전기에서 시간이 겹치는 확정 예약이나 임시 점유가 있으면 새 예약을 거절하고, 차량 커넥터를 지원하지 않는 충전기는 예약을 거절한다. 시나리오는 GIVEN/WHEN/THEN으로 쓰고, 앞 예약이 끝나는 시각과 새 예약이 시작하는 시각이 같은 경계를 포함한다. 근거는 docs/prd.md와 docs/acceptance.md이다."

## User Scenarios & Testing *(mandatory)*

모든 예시는 서울 시간 `Asia/Seoul`, 날짜는 `2026-10-06`이다.
겹침 검증에서는 커넥터가 일치하며, 커넥터 검증에서는 겹치는 예약·점유가 없다.
별도 명시하지 않은 기존 예약 자격·권한·기간·시간 단위·길이 조건은 충족한다.
시나리오는 검증 요구사항이며 실행한 테스트 결과가 아니다.

### User Story 1 - 이미 확보된 충전기 시간을 보호한다 (Priority: P1)

운전자는 같은 충전기의 다른 확정 예약 또는 유효 임시 점유와 겹치는 시간을
새로 확보할 수 없고, 겹치지 않는 연속 시간은 선택할 수 있다.
프로젝트 US-04와 US-05의 시간 확보 부분에 대응한다.

**Why this priority**: 같은 충전기의 시간을 중복 확보하면 가상 예약의 기본 약속이 깨진다.

**Independent Test**: 같은 충전기 A에 확정 예약 또는 유효 임시 점유를 준비한 뒤
아래 시간을 각각 요청하여 거절·경계 허용 결과를 확인한다.
결제 승인·점유 만료 동작 없이 사전에 정해진 점유의 유효 여부로 검증할 수 있다.

**Acceptance Scenarios**:

1. **S-01 / AC-04-3 — 부분 겹침:** **GIVEN** A에 `10:00~11:00` 확정 예약이 있다.
   **WHEN** `10:30~11:30`을 새로 예약하려 한다.
   **THEN** 겹침으로 새 시간 확보를 거절하며 기존 예약을 유지한다.
2. **S-02 / AC-04-3 — 유효 임시 점유:** **GIVEN** A에 `10:00~11:00` 유효 임시 점유가 있다.
   **WHEN** `10:30~11:30`을 예약하려 한다.
   **THEN** 확정 예약이 아니어도 새 시간 확보를 거절한다.
3. **S-03 / AC-04-3 — 끝과 시작이 같음:** **GIVEN** A에 `10:00~11:00` 확정 예약이 있다.
   **WHEN** `11:00~11:30`을 예약하려 한다.
   **THEN** 겹침으로 거절하지 않는다. 다른 제한이 없다면 예약 진입을 허용한다.
4. **S-04 / AC-04-3 — 임시 점유의 같은 경계:** **GIVEN** A에 `10:00~11:00` 유효 임시 점유가 있다.
   **WHEN** `11:00~11:30`을 예약하려 한다.
   **THEN** 경계 시각만 같으므로 겹침으로 거절하지 않는다.
5. **S-05 / AC-04-3 — 반대 방향의 같은 경계:** **GIVEN** A에 `10:00~11:00` 확정 예약 또는 유효 임시 점유가 있다.
   **WHEN** `09:30~10:00`을 예약하려 한다.
   **THEN** 새 예약 종료와 기존 시작이 같으므로 겹침으로 거절하지 않는다.
6. **S-06 / AC-04-3 — 동일·포함 구간:** **GIVEN** A에 `10:00~11:00` 확정 예약 또는 유효 임시 점유가 있다.
   **WHEN** `10:00~11:00`, `10:00~10:30`, `09:30~11:00`을 각각 요청한다.
   **THEN** 동일 구간·기존 구간 안쪽·기존 구간을 포함하는 구간 모두 겹침으로 거절한다.
7. **S-07 / AC-04-3·AC-01-1 — 다른 충전기:** **GIVEN** A에 `10:00~11:00` 확정 예약이 있고
   충전기 B는 A와 `statId + chgerId` 조합이 다르며 해당 시간에 예약·점유가 없다.
   **WHEN** B의 `10:00~11:00`을 요청한다.
   **THEN** A의 예약을 이유로 B를 거절하지 않는다. 같은 충전소여도 충전기 ID가 다르면 구분한다.

근거: [PRD 4.2.1 상태와 시간 처리](../../docs/prd.md#421-상태와-시간-처리),
[AC-04-3](../../docs/acceptance.md#ac-04-3--겹치는-시간-차단),
[AC-01-1](../../docs/acceptance.md#ac-01-1--저장된-데이터-조회).

### User Story 2 - 자기 차량의 커넥터를 지원하는 충전기를 선택한다 (Priority: P1)

운전자는 자기 차량의 커넥터 종류를 직접 선택하고,
그 종류를 지원하는 충전기만 예약할 수 있다. 프로젝트 US-02에 대응한다.

**Why this priority**: 시간이 비어 있어도 선택 커넥터를 지원하지 않으면 예약 자격을 만족하지 않는다.

**Independent Test**: 선택 완료된 커넥터와 알려진 충전기 타입을 조합하여
시간 확보나 결제 없이 지원 여부를 검증한다.

**Acceptance Scenarios**:

1. **S-08 / AC-02-6 — 일치:** **GIVEN** 운전자가 DC콤보를 선택했고 충전기는 `chgerType=04`이다.
   **WHEN** 예약을 시도한다.
   **THEN** 커넥터 조건을 만족하며 다른 제한이 없다면 예약 진입을 허용한다.
2. **S-09 / AC-02-6 — 불일치:** **GIVEN** 운전자가 DC콤보를 선택했고 충전기는 `chgerType=01`이다.
   **WHEN** 예약을 시도한다.
   **THEN** 예약을 거절하고 선택 커넥터를 지원하지 않는다는 사유를 안내한다.
3. **S-10 / AC-02-7 — 복합 타입:** **GIVEN** 충전기는 `chgerType=06`이다.
   **WHEN** DC차데모·AC3상·DC콤보·NACS를 각각 선택하여 예약을 시도한다.
   **THEN** 앞의 세 종류는 커넥터 조건을 만족하고 NACS는 불일치로 거절한다.
4. **S-11 / AC-02-7 — NACS 포함 복합 타입:** **GIVEN** 충전기는 `chgerType=10`이다.
   **WHEN** DC콤보·NACS·DC차데모를 각각 선택하여 예약을 시도한다.
   **THEN** DC콤보와 NACS는 커넥터 조건을 만족하고 DC차데모는 불일치로 거절한다.
5. **S-12 / AC-02-7 — 공식 대응표 전체:** **GIVEN** PRD 1.4의 선택 커넥터 6종과 코드 `01~11`이 있다.
   **WHEN** 모든 66개 조합의 지원 여부를 확인한다.
   **THEN** 아래 지원 코드에 포함된 조합만 커넥터 조건을 만족한다.
   이는 호환 조건 판정이며 버스전용 차량 자격이나 실제 이용을 허용한 결과가 아니다.

| 선택 커넥터 | 지원 `chgerType` 코드 | 원문 근거 |
|---|---|---|
| DC차데모 | `01`, `03`, `05`, `06` | PRD 1.4, AC-02-7 |
| AC완속 | `02` | PRD 1.4, AC-02-7 |
| AC3상 | `03`, `06`, `07` | PRD 1.4, AC-02-7 |
| DC콤보 | `04`, `05`, `06`, `08`, `10` | PRD 1.4, AC-02-7 |
| NACS | `09`, `10` | PRD 1.4, AC-02-7 |
| DC콤보2(버스전용) | `11` | PRD 1.4, AC-02-7 |

`08`의 공식 설명은 DC콤보(완속)이며 DC콤보 대응과 완속 구분을 유지한다.
`09`은 현재 원본에 없지만 공식 대응표에 정의되어 있다. DC콤보와 DC콤보2를 합치지 않는다.

근거: [PRD 1.4](../../docs/prd.md#14-커넥터와-충전기-타입-대응-근거),
[PRD 4.2.2](../../docs/prd.md#422-운전자-선택-커넥터와-예약-자격),
[AC-02-6](../../docs/acceptance.md#ac-02-6--선택-커넥터-일치불일치),
[AC-02-7](../../docs/acceptance.md#ac-02-7--공식-코드-대응과-복합-타입).

### User Story 3 - 두 조건과 기존 제한을 함께 지킨다 (Priority: P1)

운전자는 시간 겹침과 커넥터 호환을 모두 만족해야 예약할 수 있으며,
두 규칙 통과가 기존 예약 제한을 해제한 것으로 안내되지 않는다.

**Why this priority**: 조건 하나의 통과만으로 전체 예약을 허용하면 다른 보호 규칙을 우회한다.

**Independent Test**: 기존 자격 조건을 충족하는 사례에서 겹침·호환 조합을 각각 확인하고,
별도 사례에서 기존 제한을 남겨 두어 예약 거절이 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **S-13 / AC-04-3·AC-02-6 — 겹침·일치:** **GIVEN** 커넥터는 일치하지만 같은 충전기에 겹치는 확정 예약이 있다.
   **WHEN** 새 예약을 시도한다. **THEN** 커넥터 일치와 관계없이 겹침으로 거절한다.
2. **S-14 / AC-04-3·AC-02-6 — 연속·불일치:** **GIVEN** 기존 예약 종료와 새 예약 시작은 `11:00`으로 같지만 커넥터는 불일치이다.
   **WHEN** 새 예약을 시도한다. **THEN** 겹침은 아니지만 커넥터 불일치로 거절한다.
3. **S-15 / AC-04-3·AC-02-6 — 겹침·불일치:** **GIVEN** 같은 충전기의 시간도 겹치고 커넥터도 불일치이다.
   **WHEN** 새 예약을 시도한다. **THEN** 거절하며 새 구간을 확보하거나 확정하지 않는다.
   거절 사유의 표시 순서는 이 명세에서 정하지 않는다.
4. **S-16 / AC-02-8 — 기존 제한 유지:** **GIVEN** 시간은 겹치지 않고 커넥터는 일치하지만
   이용 제한·삭제·운영시간 조건 불충족·고장·점검·상태 불명·운영자 차단 중 하나가 있다.
   **WHEN** 예약을 시도한다. **THEN** 기존 제한으로 예약을 거절한다.

근거: [PRD 4.2.2](../../docs/prd.md#422-운전자-선택-커넥터와-예약-자격),
[AC-02-8](../../docs/acceptance.md#ac-02-8--기존-예약-제한과-함께-적용), AC-04-3, AC-02-6.

### Edge Cases

- 끝과 시작이 같은 경계는 두 방향 모두 겹침이 아니다(S-03~S-05).
- 부분 겹침뿐 아니라 동일·포함 구간도 거절한다(S-01·S-02·S-06).
- 충전소가 같아도 충전기 식별 조합이 다르면 해당 예약은 서로의 겹침 근거가 아니다(S-07).
- 복합 타입은 지원 종류별로 판정하고, 존재하지 않는 종류를 지원한다고 추정하지 않는다(S-10~S-12).
- 호환되지만 겹치는 경우, 연속 시간이지만 불일치인 경우 모두 거절한다(S-13~S-15).
- 유효 임시 점유만 겹침 근거이다. 정확히 10분 만료·늦은 승인·점유 해제 방식은 C-04·C-07로 남긴다.
- 커넥터 미선택·미정의 코드·선택 변경·어댑터·버스전용 차량 자격은 AC-02-9/C-11로 남긴다.
  미확정 입력을 임의로 성공이나 기본 커넥터로 처리하는 요구를 추가하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 충전기는 `statId + chgerId` 조합으로 구분해야 한다.
  다른 충전기의 예약만을 이유로 겹침 거절하지 않아야 한다(S-07; AC-01-1·AC-04-3).
- **FR-002**: 예약 이용 구간은 시작 포함·종료 제외로 판단해야 한다.
  기존 종료와 새 시작이 같거나 새 종료와 기존 시작이 같은 경우는 겹침이 아니어야 한다
  (S-03~S-05; PRD 4.2.1·AC-04-3).
- **FR-003**: 같은 충전기의 확정 예약 또는 유효 임시 점유와 일부라도 시간이 겹치면
  새 구간 확보를 거절해야 한다. 동일·포함 구간도 포함한다(S-01·S-02·S-06; AC-04-3).
- **FR-004**: 선택 커넥터를 지원하지 않는 충전기는 예약을 거절하고
  커넥터 불일치 사유를 안내해야 한다(S-09~S-12·S-14; AC-02-6·AC-02-7).
- **FR-005**: 알려진 커넥터와 충전기 타입의 지원 관계는 PRD 1.4와 AC-02-7의 대응표를
  따라야 한다. 복합 타입은 포함된 각 종류를 지원하며 다른 종류는 지원하지 않아야 한다
  (S-08~S-12; AC-02-6·AC-02-7).
- **FR-006**: 시간 겹침 없음과 커넥터 일치를 모두 만족할 때만 이 두 규칙의 통과로 판정해야 한다.
  하나라도 불충족하면 예약을 거절하며 새 구간을 확보하거나 확정하지 않아야 한다
  (S-13~S-15; AC-04-3·AC-02-6).
- **FR-007**: 두 규칙 통과만으로 기존 예약 자격·권한·기간·시간 조건을 우회해서는 안 된다.
  기존 제한은 계속 적용해야 한다(S-16; AC-02-8·PRD 4.2.2).

### Key Entities *(include if feature involves data)*

- **충전기**: 충전소 ID와 충전기 ID의 조합, 충전기 타입과 그에 따른 지원 커넥터 종류를 가진다.
- **새 예약 요청**: 대상 충전기, 이용 시작·종료 시각, 운전자가 선택 완료한 커넥터를 가진다.
- **확정 예약**: 승인 확인 후 확정된 예약이며 대상 충전기와 이용 시간 구간을 가진다.
- **유효 임시 점유**: 현재 유효하다고 판정된 시간 확보이며, 확정 예약과 구분된다.
  겹침 판단에는 점유 만료 시각이 아닌 확보한 이용 구간을 사용한다.
- **예약 규칙 판정**: 이 두 규칙의 통과 또는 거절 결과이다.
  규칙 통과는 결제 승인·예약 확정·현장 이용 보장을 의미하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: S-01~S-07의 모든 시간 사례에서 명시한 거절·비겹침 결과가 100% 일치한다.
  특히 확정 예약과 유효 임시 점유 모두 종료·시작이 같은 경계에서 잘못 거절한 건수가 0건이다.
- **SC-002**: S-12의 66개 커넥터·타입 조합에서 지원 관계가 대응표와 100% 일치한다.
- **SC-003**: S-13~S-16의 조합·기존 제한 사례에서 불충족 요청을 허용한 건수가 0건이다.
- **SC-004**: S-09와 S-14에서 운전자가 결과 안내로 커넥터 불일치가 예약 거절 원인임을
  확인할 수 있고, S-03·S-04의 경계 일치가 겹침으로 안내되는 건수가 0건이다.

위 수치는 명세의 사례 검증 목표이며 실제 서비스 성과나 현재 테스트 통과 결과가 아니다.

## Assumptions

- 이 명세는 PRD·AC의 확정 정책을 구체적인 사례로 정리하며 새로운 제품 정책을 만들지 않는다.
- 범위는 겹침·커넥터 판정이다. 결제, 점유 생성·만료, 동시 확보 실행,
  취소·노쇼·승계·저장·로그인·화면 구성은 구현 범위에 포함하지 않는다.
- 대상 충전기·유효 점유 여부·선택 완료된 알려진 커넥터와 타입은 앞 단계에서 준비된 입력이다.
  임시 점유는 상태만 유효하다고 가정하며 유효 기한 계산 규칙을 이 명세가 확정하지 않는다.
- C-04·C-07·C-11과 AC-05-3·AC-02-9의 미정 사항은 이번 판정 범위 밖에 유지한다.
  관련 동작까지 구현 범위를 넓힐 때는 먼저 사용자 답변과 PRD·AC·작업 목록 갱신이 필요하다.
- 대응 작업은 T-04·T-10·T-13·T-17의 관련 부분이며, 이 명세 작성은 해당 T의 완료가 아니다.
- 헌법의 테스트 우선 절차에 따라 실제 구현 전 AC별 테스트를 먼저 작성하고
  사용자 확인과 실패 실행을 거쳐야 한다. 구현 중에는 테스트 파일을 변경하지 않는다.
  이 명세의 시나리오는 테스트 파일 작성·사용자 테스트 확인·실패 실행을 대신하지 않는다.

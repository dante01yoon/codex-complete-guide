# ev-booking 작업 지침

이 파일은 100줄 이내의 작업 목차로 유지한다. 자세한 정책·사례·완료 조건은 아래 `docs` 문서를 따른다.

## 작업 시작 전에 읽을 문서

이 폴더에서 작업을 시작하기 전에 다음 세 문서를 모두 먼저 읽는다.

1. [docs/prd.md](docs/prd.md): 제품 목적, 범위, 확정 정책, 열린 질문
2. [docs/acceptance.md](docs/acceptance.md): US별 GIVEN/WHEN/THEN 수용 기준과 조건부 기준
3. [docs/tasks.md](docs/tasks.md): 구현 작업, 관련 US·AC, 완료 조건, 선행 작업, 구현 전 확인 목록

## 정책과 작업 범위

- 문서에 없는 정책은 임의로 정하지 말고 사용자에게 물어본다. 금액, 시간 경계, 자격, 상태 전이, 대기 순서, 권한, 실패 처리도 이 원칙을 따른다.
- 문서끼리 충돌하거나 해석이 여러 가지면 관련 문서·US·AC·T 번호를 제시하고 사용자에게 확인한다. 작업 목록만으로 PRD·수용 기준의 정책을 바꾸지 않는다.
- 조건부 AC와 tasks.md의 C 항목은 미확정 상태이다. 단순 문서 승인만으로 확정됐다고 간주하지 않는다. 해당 동작을 구현하기 전에 답변을 받고 관련 문서를 함께 갱신한다.
- 기술 구성이 아직 확정되지 않았다면 T-01의 합의부터 수행한다. 제품 정책에 영향을 주지 않는 내부 구현 선택은 합의한 구성 안에서 결정할 수 있다.
- 요청받은 T 작업의 선행 조건과 실제 완료 근거를 확인하고, 그 작업의 범위와 완료 조건에 맞춰 수행한다. 필요한 추가 작업은 별도로 설명한다.

## 막혔을 때의 처리

- 훅이 작업을 차단하면 다른 도구·명령·경로로 우회하거나 훅을 수정·비활성화하지 않는다. 작업을 `BLOCKED`로 멈추고, 차단한 훅·시도한 작업·차단 이유·관련 T/AC와 사용자가 고를 수 있는 선택지를 보고한다. 사용자 결정 전에는 차단된 작업을 재개하지 않는다.
- 정책 변경으로 테스트 수정이 필요하면 코덱스는 테스트를 고치지 않고 해당 구현을 `BLOCKED`로 중단한다. 바뀔 수용 기준의 AC 번호·현재 기준·변경안, 영향받는 테스트 파일·정확한 테스트 이름·현재/변경 후 기대 결과를 정리해 사람에게 넘긴다. 사람이 정책·문서·테스트를 갱신한 뒤 헌법의 사용자 확인·실패 확인 절차를 거쳐 구현을 재개한다.
- 같은 테스트가 세 번 연속 실패하면 더 수정하거나 네 번째 재시도를 하지 않고 작업을 멈춘다. 테스트 결과는 `FAIL`, 작업 상태는 `BLOCKED`로 기록한다. 테스트 파일·정확한 이름·관련 AC, 세 번의 실행 명령·실패 이유·시도한 수정·결과를 [docs/harness.md](docs/harness.md)의 실패 기록 형식으로 남기고 사람이 검토할 수 있도록 보고한다. 키·비밀값은 기록하지 않는다.

## 예약·결제 도메인 규칙

- 금액은 원 단위 정수로만 다룬다. 예약금·환불액 정책은 [docs/prd.md](docs/prd.md)의 4.2를 따른다.
- 시간은 서울 시간(`Asia/Seoul`)의 시연용 시계를 기준으로 판정하고, 예약 구간은 시작 포함·종료 제외인 `[시작, 종료)`로 다룬다. 세부 경계는 [docs/prd.md](docs/prd.md)의 4.2·4.2.1과 [docs/acceptance.md](docs/acceptance.md)를 따른다.
- 예약 상태 이름과 상태가 바뀌는 순서는 [docs/prd.md](docs/prd.md)를 따른다. 미정 상태·전이는 임의로 추가하지 않는다.
- 환불·체크인·겹침 규칙의 구현은 `src/rules`의 순수 함수에만 둔다. 화면이나 결제 연결 코드에 규칙을 중복 구현하지 않는다. 관련 기준과 작업은 [docs/acceptance.md](docs/acceptance.md), [docs/tasks.md](docs/tasks.md)의 C-10·T-13·T-22·T-25·T-35를 따른다.
- 결제·환불은 `test_`로 시작하는 토스페이먼츠 테스트 키만 사용한다. 키 값은 `.env`에만 두고 코드·문서·로그·버전 관리에 노출하지 않는다. 결제·환불 흐름은 [docs/tasks.md](docs/tasks.md)의 T-15~T-20·T-47을 따른다.

## 데이터·시연·검증

- 학습용 로컬 모바일 웹이다. 배포하지 않는다. 실제 충전소 이용·주차면·충전량을 보장하지 않는다.
- 충전소 원본은 `../ev-map/data`이다. 원본을 임의로 수정하거나 재수집하지 않는다.
- 실제 결제를 수행하지 않는다. 서비스 범위와 데이터 한계는 [docs/prd.md](docs/prd.md)의 1.3·4를 따른다.
- 관련 AC를 검증하고 `PASS / FAIL / BLOCKED / NOT_RUN`을 정확히 기록한다. 정적 확인·모의 처리·브라우저·토스 테스트 실연결을 구분하며, 상세 기록 방법은 [docs/tasks.md](docs/tasks.md)의 9를 따른다.

# 내 예약 — 구현 전 검토안

사용자 요청: 운전자 내 예약, 지금 취소할 때의 환불액, 시작까지 남은 시간,
확인 후 모의 취소, 2시간 초과·1시간·20분 전 예약 3개, 직접 화면 검증.

## 화면과 구현 범위

- 기존 `npm run dev`의 빈 `web/index.html`을 HTML/CSS/JavaScript 화면으로 확장한다.
  새 프레임워크나 의존성을 추가하지 않는다.
- 카드마다 충전소·충전기 식별자, 서울 시작/종료, 체크인 기한,
  예약 확정 상태, 예약금 3,000원(모의), 남은 시간, 현재 환불 예정액을 표시한다.
- 취소 버튼은 확인창을 연다. 충전소·시간·환불액·미반환액을 보여 주고
  ‘예약 유지’와 ‘모의 취소 확정’을 제공한다. 확인 전에는 상태를 변경하지 않는다.
- 취소 결과는 카드에 사용자 취소·모의 반환 금액으로 남기고 재취소를 막는다.
  0원도 ‘환불 없음’으로 명확하게 표시한다. 대기 승계와 외부 환불은 실행하지 않는다.
- 휴대폰은 세로 카드, 큰 화면은 여유 있는 목록 배치로 만든다.
  가상 예약·모의 결제 안내를 화면에 표시한다.

## 시연 데이터·시간·저장 제안

- 서버가 제공하는 고정 시연 시각 `2026-10-12 10:00:00 Asia/Seoul` 사용.
  브라우저·컴퓨터 시계로 보정하지 않는다. 시계 진행·역행·초기화 UI는 이번 범위 밖이다.
- 시작은 12:30 / 11:00 / 10:20, 각 60분 이용. 남은 시간 150 / 60 / 20분.
  금액은 기존 `src/rules/refund.ts`를 호출해 3,000 / 1,500 / 0원으로 계산한다.
- 예약 3개는 한 시연 운전자의 고정 데이터이다. 원본 충전소 파일은 읽기만 한다.
  충전소 이름·식별자는 저장된 원본에서 가져오고 가상 예약으로 표시한다.
- 이번 요청에서 승인한 1건 제한·00/30분 시작 예외는 시연 초기 데이터에만 적용한다.
  일반 예약 정책 AC-03-2·AC-04-2 및 기존 규칙 테스트는 변경하지 않는다.
- 취소 상태는 서버 메모리에 보관하여 새로고침에도 유지하고, 서버 재시작 시 초기화한다.
  인증 기능은 구현하지 않으며 ‘시연 운전자’라고 명시한다. 임의 계정 선택 API는 제공하지 않는다.
- 표시·취소용 도메인 계산은 `src/rules`, HTTP·메모리 보관은 `src/server`,
  렌더링과 확인창은 `web`에 둔다. 실제 토스 연결·환불 실패 정책은 이번 범위 밖이다.

## 관련 작업과 선행 조건

T-21/T-24의 조회·확인 화면, T-23의 모의 취소 부분을 수행하는 별도 시연 범위다.
T-22는 기존 환불 순수 함수를 재사용한다. T-08 로그인, T-17 결제 확정,
T-18 외부 환불은 실제 구현 근거가 없으므로 완료로 보고하지 않는다.
C-10 중 이번 화면의 기본 웹 기술·메모리 저장, C-09 중 고정 시계만 승인 대상으로 제안한다.
US-06/07 및 AC-06-1/2, AC-07-1~4의 이번 시연 부분을 검증한다.

## 테스트 확인 관문

새 테스트: `specs/my-reservations.acceptance.test.mjs`.
기존 보호 대상 `tests/rules`는 변경하지 않는다. 새 시연 테스트를 별도로 검토한다.

1. AC-06-1: 서버 시계와 3개 예약의 남은 시간·환불 예정액·기한·모의 표시.
2. AC-07-1: 150분 전 취소는 사용자 취소, 3,000원 모의 반환.
3. AC-07-2: 60분 전 취소는 1,500원 모의 반환.
4. AC-07-3: 20분 전 취소는 0원, 환불 없음.
5. AC-07-4: 반복 취소는 결과와 반환액 유지, 다른 예약 보존.
6. AC-06-2: 취소 결과를 재조회해도 유지, 외부 결제는 NOT_RUN.
7. 브라우저 AC-06-1/2·AC-07-1~3: 확인창 닫기는 상태 유지,
   확인 후 각 금액 표시, 모바일 가로 넘침 없음.

사용자가 설계와 테스트를 명시적으로 확인한 후 테스트를 실행해 미구현 실패를 기록한다.
그 뒤 구현하고 동일 테스트·규칙·타입·린트와 390×844/1440×900 화면을 검증한다.
실제 화면 캡처를 열어 배치와 결과를 확인하고 PASS/FAIL/BLOCKED/NOT_RUN을 기록한다.

2026-10-11 사용자가 설계와 테스트를 명시 확인했다. 승인한 범위로 구현하고
모의 기능·브라우저 검증을 수행했다. 실제 결과는 `my-reservations-validation.md` 참조.

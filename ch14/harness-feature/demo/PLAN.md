# 하네스 확인 화면

요청 범위: demo 폴더를 복사해 사용할 수 있는 로컬 확인 화면, 포트 4174,
기존 환불 규칙·실제 검사 결과·tests 변경 여부 표시. 제품 기능 T-24나
시계 제어 T-45를 구현하거나 제품 정책 C 항목을 확정하는 작업은 아니다.

## 화면과 데이터

- 환불: src/rules/refund.ts의 기존 순수 함수를 서버에서 호출한다.
  AC-07-1~3의 서울 시각 예시 8개를 표시한다. 실제 환불은 실행하지 않는다.
- 검사: 설정한 명령을 프로젝트 루트에서 실행하고 종료 코드와 실행 시각을 표시한다.
  규칙 테스트·타입 검사는 각각 표시한다. 미실행 NOT_RUN, 명령 미준비 BLOCKED,
  실제 실패 FAIL, 종료 코드 0 PASS. 부분 검증을 전체 서비스 검증으로 확대하지 않는다.
- tests: Git HEAD 기준 추적 파일 내용과 작업 트리를 비교하고 미추적 파일을 추가로 조회한다.
  수정·추가·삭제를 구분한다. Git 미준비·HEAD 없음은 BLOCKED로 표시한다.
  조회는 파일이나 Git 인덱스를 변경하지 않는다. 커밋 후 HEAD가 바뀌는 한계를 안내한다.
- 하네스: 문서·순수 함수·테스트 보호·중단 규칙의 역할과 자동화 한계를 짧게 안내한다.

## 재사용과 실행

Node.js 24 기본 모듈과 HTML/CSS/JavaScript를 사용하고 새 의존성은 추가하지 않는다.
demo 설정 파일의 검사 명령과 환불 모듈 경로를 바꾸어 다른 프로젝트에 적용한다.
누락된 어댑터는 BLOCKED로 표시한다. 서버는 127.0.0.1:4174에 바인딩한다.
검사 요청은 같은 출처에서만 받으며 임의 명령이나 경로를 HTTP 입력으로 받지 않는다.
화면 새로고침은 조회만, 검사 실행 버튼은 설정된 검사만 실행한다.

## 구현 전 확인할 검증

demo/acceptance.test.mjs (Node.js 내장 test runner):

1. AC-DEMO-01: 실제 환불 함수의 경계값 8개가
   3000 / 3000 / 1500 / 1500 / 1500 / 0 / 0 / 0원이다.
   시간대는 Asia/Seoul, 외부 결제는 NOT_RUN이다.
2. AC-DEMO-02: 미설정·성공·실패·명령 없음이
   NOT_RUN / PASS / FAIL / BLOCKED이며 실제 종료 코드를 보존한다.
3. AC-DEMO-03: 임시 Git 저장소에서 변경 없음 및 수정·추가·삭제를 구분하고
   조회 전후 Git 상태가 동일하다. 프로젝트 하위 경로는 BLOCKED이다.

프로젝트의 기존 tests 폴더는 수정하지 않는다. 사용자 확인 후 이 검증의
실패를 먼저 확인하고 구현한다. 구현 후 동일 검증, 기존 규칙 테스트,
타입 검사, 데스크톱·모바일 브라우저 확인을 수행하고 결과를 기록한다.
